# AI PPT Generator

AI PPT Generator is an AI-powered presentation builder that turns a topic into a slide outline and a downloadable PowerPoint deck.

The project has two parts:

- `app.py`: a Streamlit chat-style UI for creating and editing presentations
- `backend/main.py`: a FastAPI service that generates outlines and builds PPT files

## What it does

- Generates slide outlines from a topic
- Builds PowerPoint decks with clean, presentation-ready content
- Supports tone-based output such as `Professional`
- Accepts optional logo and content image uploads
- Sanitizes LLM output so markdown, icon tokens, and emoji do not leak into slides
- Applies theme colors and presentation layouts during deck creation

## How it works (detailed)

This project is split into a lightweight UI (`app.py`) and a backend API (`backend/main.py`). The system follows a defensive pipeline so no raw LLM artifacts reach the final PPT:

1. User message (Streamlit UI or API client) is sent to the backend or processed locally in `app.py`.
2. Natural Language Understanding: `classify_ppt_intent()` ([backend/services/intent_classifier.py](backend/services/intent_classifier.py#L1)) performs LLM-first classification into a strict JSON schema. If the LLM is unavailable or uncertain, a conservative regex fallback runs.
3. Conversational Reasoning: `reasoning_layer()` ([backend/services/intelligence_layer.py](backend/services/intelligence_layer.py#L1)) applies hard semantic rules, extracts explicit slide/presentation references, enforces safety (e.g. never silently treat unknown as `add_slide`), and resolves context from the conversation state.
4. Execution Gate: `_should_execute_directly()` decides whether to act immediately or ask a clarification based on confidence and required slots.
5. Service Execution: `ppt_service` ([backend/services/ppt_service.py](backend/services/ppt_service.py#L1)) handles content generation, flattening, sanitization, layout/theming, and PowerPoint rendering using `python-pptx`.
6. Response Generation: `generate_response()` ([backend/services/response_generator.py](backend/services/response_generator.py#L1)) composes a short confirmation message; LLM polishing is optional for complex edits.
7. State & UI Update: Streamlit `st.session_state` is updated, and the UI either shows results or a follow-up question generated by `_polish_next_question()`.

## Per-operation workflows (step-by-step)

Each user intent flows through the same top-level pipeline above. The following lists the concrete steps for common operations.

- Add Slide (`add_slide`)
        1. User: "Add a slide on Market risks after slide 3."
        2. `classify_ppt_intent()` extracts `intent=add_slide`, `position=after`, `anchor_slide=3`, and `content` if provided.
        3. `reasoning_layer()` sets `slide_id=None` for new slides, validates `position` and `content`, and fills `missing_entities` when needed.
        4. If `_should_execute_directly()` passes (content + placement + confidence) then `ppt_service` inserts a slide object, runs flatten→clean→validate, and updates the outline.
        5. `create_ppt()` is called when a PPT file is requested; UI state and confirmation are updated.

- Add Points / Append Bullets (`add_points`, `update_slide` with `add_content`)
        1. Classifier marks `sub_intent=add_content` and `slide_id`.
        2. `reasoning_layer()` resolves explicit or current slide context and converts vague continuations ("more", "another") into appends.
        3. Execute: new bullets are cleaned with `_clean_bullet_text()` and appended to the slide structure.

- Transform / Update / Edit Slide (`transform_content`, `update_slide`, `edit_slide`)
        1. Classifier sets `sub_intent` (rewrite/shorten/bulletize) and `slide_id`.
        2. `reasoning_layer()` may add a confidence preface when scope was inferred.
        3. Execute: the slide content is sent to the generator/transformer; output is flattened, sanitized, and written back.

- View / Explain Slide (`view_slide`, `explain_slide`)
        1. Explicit-number patterns are high-priority in `reasoning_layer()`.
        2. Execute: UI shows the slide content; `explain_slide` can run an LLM explanation path to produce speaker notes.

- Delete / Merge / Move / Swap Slides
        1. Classifier extracts required indices; `reasoning_layer()` enforces presence of at least two ids for merges.
        2. Execute: outline list is updated (remove, merge contents, reorder), then cleaned and re-rendered if required.

- Regenerate Slide / Bulk Operations / Design Changes / Presentation Mode
        1. These are deck-level intents. The classifier sets `action_type=deck` and `sub_intent` where applicable.
        2. Execute: operations typically loop over slides and call generation/transform routines per-slide. Large-impact operations may prompt for confirmation.

## Sanitization & Safety

- All text passed to rendering is cleaned by `ppt_service`'s `_clean_bullet_text()` and `_validate_and_clean_content()` which:
        - Strip icon tokens (e.g., `check-circle`, `arrow-right`) and invented icon words.
        - Remove Markdown bold markers (`**bold**`) while keeping text where appropriate.
        - Remove emoji tokens (`:smile:`) and Unicode emoji characters.
        - Remove leading bullets/symbols and suspicious head tokens invented by LLMs.
- `reasoning_layer()` prevents ambiguous routing (e.g., never converting `unknown` to `add_slide`).
- Endpoints use timeouts and try/except to guard against long LLM calls.

## Intent / Confidence Rules

- LLM-produced confidence < 0.60 typically triggers `intent=unknown` and a clarification question.
- Slide-level intents usually require a `slide_id` to execute; otherwise they will ask for the slide number.
- For moderate confidence (0.60–0.79) where scope is inferred, the UI may show a short scope preface and proceed; for lower confidence the system asks for clarification.

## API & Developer Notes

- Health: `GET /` returns a simple health message (in [backend/main.py](backend/main.py#L1)).
- Generate outline: `POST /generate-outline` — sends `topic`, `num_slides`, `tone`, optional `theme_colors`. Returns a normalized slide outline.
- Build PPT: `POST /build-ppt` — accepts `slides_json`, optional `logo` and `content_image`. Returns cleaned slide list and base64 PPT bytes.
- Intent debug: `POST /classify-intent` — send `{message, ppt_id?, slide_id?}` to inspect the classifier output.

## Running locally

1. Create and activate a virtualenv and install dependencies:

```bash
python -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

2. Start the FastAPI backend (port 9000):

```bash
uvicorn backend.main:app --reload --port 9000
```

3. Start the Streamlit UI in another terminal:

```bash
streamlit run app.py
```

4. Open the Streamlit UI in your browser and interact.

## Testing & Debugging tips

- Use the `/classify-intent` endpoint to test how a sentence is parsed and what slots are extracted before executing actions.
- Try edge cases with icon tokens and markdown to verify sanitization works:
        - Input a sentence that begins with `**check-circle**` or `:rocket:` and verify the rendered bullet is cleaned.
- For large deck changes, test on small decks first and increase complexity.

## API Endpoints

### `GET /`

Health check for the backend.

Response:

```json
{"message":"FastAPI backend running 🚀"}
```

### `POST /generate-outline`

Generates slide content for a topic.

Form fields:

- `topic` - required
- `num_slides` - optional, default `5`
- `tone` - optional, default `Professional`
- `theme_colors` - optional JSON string

### `POST /build-ppt`

Builds the PowerPoint file from generated slide data.

Form fields:

- `topic` - required
- `tone` - optional, default `Professional`
- `slides_json` - required JSON string containing slide data
- `logo` - optional file upload

The response includes:

- the cleaned slide list
- a base64-encoded PPT file

## How It Works

1. The UI sends a topic to the backend
2. The backend uses Azure OpenAI to generate an outline
3. Slide content is cleaned and normalized
4. The service renders the final PowerPoint deck with `python-pptx`

The generation pipeline is intentionally defensive:

- flatten AI output
- clean text
- validate content
- render slides

This keeps icons, markdown, and noisy tokens out of the final presentation.
